NEDS STORE – Phase 1 Review & Improvement Document


Point No. 1 – Enterprise Delivery Charge Engine


Priority: Critical (Mandatory before Phase 1 Completion)


Module Name:
Enterprise Delivery Charge Engine


Current Status:


The current Super Admin Panel contains only two delivery-related settings:


1. Standard Delivery Charge
2. Free Delivery Above


This implementation is not suitable for an enterprise-grade hyperlocal multi-vendor marketplace because it applies a fixed delivery charge to every order regardless of distance, product weight, or delivery complexity.


A customer located 1 KM away and another customer located 12 KM away should never be charged the same delivery fee. Likewise, delivering a lightweight grocery item and delivering a refrigerator should not have the same delivery cost.


Therefore, the existing delivery charge system must be completely redesigned into a configurable Enterprise Delivery Charge Engine.


Objective:


Create a complete Delivery Charge Engine that allows the Super Admin to control every delivery pricing rule from one place without modifying the application code.


Every delivery charge displayed in the Customer App must be calculated dynamically using the Business Rules configured by the Super Admin.


No delivery price should be hardcoded anywhere in the Android App, Backend, or Database.


Required Features:


Feature 1: Minimum Delivery Distance


The Super Admin must be able to define the minimum delivery distance.


Example:


Minimum Delivery Distance = 2 KM


Business Rule:


If the customer is located within the first 2 KM from the seller, only the Minimum Delivery Charge will be applied.


Examples:


Distance = 0.8 KM
Delivery Charge = Minimum Charge


Distance = 1.5 KM
Delivery Charge = Minimum Charge


Distance = 2 KM
Delivery Charge = Minimum Charge


------------------------------------------------------------


Feature 2: Minimum Delivery Charge


The Super Admin must be able to configure the base delivery charge.


Example:


Minimum Delivery Charge = ₹20


This amount will be charged only for deliveries falling within the configured minimum delivery distance.


------------------------------------------------------------


Feature 3: Per Kilometer Delivery Charge


The Super Admin must be able to define the additional delivery charge applicable after the minimum delivery distance.


Example:


Per Kilometer Charge = ₹7


Example Calculation:


Minimum Distance = 2 KM


Minimum Charge = ₹20


Customer Distance = 5 KM


Remaining Distance = 3 KM


Additional Charge = 3 × ₹7 = ₹21


Final Delivery Charge = ₹41


The calculation must happen automatically.


------------------------------------------------------------


Feature 4: Maximum Delivery Radius


The Super Admin must be able to configure the maximum serviceable delivery radius.


Example:


Maximum Delivery Radius = 15 KM


Business Rule:


If the customer's location exceeds the configured delivery radius, the order should not be accepted.


The Customer App should display:


"Sorry, delivery service is currently unavailable in your area."


The Admin should be able to modify this value at any time.


------------------------------------------------------------


Feature 5: Free Delivery Threshold


The Super Admin must be able to configure the minimum order amount eligible for free delivery.


Example:


Free Delivery Above = ₹1000


Business Rule:


If Order Value ≥ ₹1000


Final Delivery Charge = ₹0


This value must remain configurable.


------------------------------------------------------------


Feature 6: Weight Based Delivery Charges


The system must support configurable weight slabs.


Example:


0–5 KG = ₹0


5–10 KG = ₹20


10–20 KG = ₹50


20 KG and Above = ₹100


Business Rule:


The total order weight should be calculated automatically.


If the weight falls within a configured slab, the corresponding delivery charge must be added automatically.


------------------------------------------------------------


Feature 7: Bulky Product Delivery Charges


Some products occupy more delivery space despite having lower weight.


Examples:


Television


Refrigerator


Furniture


Bed


Sofa


Washing Machine


Therefore, the Super Admin must be able to define additional delivery charges for bulky products.


Example:


Television = ₹80


Refrigerator = ₹150


Furniture = ₹250


These values should be editable anytime.


------------------------------------------------------------


Feature 8: Delivery Charge Formula


The Delivery Engine should calculate delivery charges using the following sequence.


Step 1


Calculate road distance between Seller and Customer using Google Maps.


Step 2


Check Maximum Delivery Radius.


If customer is outside the service area,
reject the order.


Step 3


Apply Minimum Delivery Charge.


Step 4


Calculate Additional Distance Charge.


Step 5


Calculate Weight Charge.


Step 6


Calculate Bulky Product Charge.


Step 7


Check Free Delivery Rule.


If applicable,


Final Delivery Charge = ₹0


Otherwise,


Final Delivery Charge =
Minimum Charge +
Additional Distance Charge +
Weight Charge +
Bulky Product Charge


------------------------------------------------------------


Feature 9: Admin Control Panel


The Delivery Charge Engine must contain editable fields for:


Minimum Delivery Distance


Minimum Delivery Charge


Per Kilometer Charge


Maximum Delivery Radius


Free Delivery Threshold


Weight Slab Configuration


Bulky Product Charges


Enable / Disable Free Delivery


Every change made by the Super Admin should become active immediately throughout the platform without requiring any application update.


------------------------------------------------------------


Feature 10: Customer Checkout Display


Before payment, the Customer App must clearly display the complete delivery charge calculation.


Example:


Distance : 5 KM


Minimum Charge : ₹20


Additional Distance Charge : ₹21


Weight Charge : ₹20


Bulky Product Charge : ₹0


Final Delivery Charge : ₹61


The customer should always know how the delivery charge has been calculated.


------------------------------------------------------------


Database Requirements


The Business Rules collection should store all Delivery Charge configurations.


Suggested Fields:


minimum_delivery_distance


minimum_delivery_charge


per_km_charge


maximum_delivery_radius


free_delivery_threshold


weight_charge_rules


bulky_item_charge_rules


is_free_delivery_enabled


Every delivery calculation must read values dynamically from these fields.


------------------------------------------------------------


API Requirements


Create or update APIs so that:


Admin can update Delivery Rules.


Customer App can fetch latest Delivery Rules.


Checkout API automatically calculates delivery charges.


Future rule changes should not require Android App updates.


------------------------------------------------------------


Validation Rules


Minimum Distance cannot be negative.


Minimum Charge cannot be negative.


Per KM Charge cannot be negative.


Maximum Radius must be greater than Minimum Distance.


Weight Slabs should not overlap.


Bulky Product Charges cannot be negative.


If Free Delivery is enabled, the threshold amount must be greater than zero.


------------------------------------------------------------


Expected Result


After implementing this module, NEDS STORE will have a complete Enterprise Delivery Charge Engine.


The Super Admin will have full control over all delivery pricing policies.


The Android App, Backend, and Admin Panel will automatically follow these rules without requiring future code modifications whenever delivery pricing changes.


Implementation Instructions for Emergent AI


Implement this module by modifying only the required backend services, Business Rules Engine, Database Models, Delivery Calculation Engine, Admin UI, and related APIs.


Do not regenerate unrelated modules.


Reuse the existing architecture, components, APIs, database models, and UI wherever possible.


Maintain full compatibility with the locked Version 1.0 architecture and the approved Enterprise Documentation.

Point No. 2 – Enterprise Payment Configuration Module


Priority: Critical (Mandatory before Phase 1 Completion)


Module Name:
Enterprise Payment Configuration Module


Current Status:

Although Version 1.0 uses UPI Intent Payment and Cash on Delivery (COD), there is currently no section where the Super Admin can configure the bank account or UPI ID that will receive customer payments.

Therefore, a complete Enterprise Payment Configuration Module must be implemented.
